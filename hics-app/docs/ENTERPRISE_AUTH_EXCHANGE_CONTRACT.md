# Enterprise Auth Exchange Contract

This document defines the backend contract for exchanging OIDC authorization codes for NyxHICSlab app sessions. It is implemented in `api/auth/exchange.js`.

## Endpoint

- Method: `POST`
- Path: `/api/auth/exchange`
- Content-Type: `application/json`

## Request Body

```json
{
  "provider": "entra",
  "code": "AUTHORIZATION_CODE",
  "codeVerifier": "PKCE_CODE_VERIFIER",
  "redirectUri": "https://app.nyxhicslab.com/auth/callback",
  "remember": true
}
```

Fields:
- `provider`: `entra` or `okta`
- `code`: OIDC authorization code from identity provider callback
- `codeVerifier`: PKCE verifier generated by the frontend (43-128 characters)
- `redirectUri`: Must match the redirect URI registered with the identity provider, and `ALLOWED_OIDC_REDIRECT_URI` when set
- `remember` (optional, default `true`): `false` makes the refresh cookie end with the browser session

## Success Response

- Status: `200 OK`
- Header: `Set-Cookie: nyx_rt=<refresh token>; Path=/api/auth; HttpOnly; Secure; SameSite=Strict[; Max-Age=...]`

```json
{
  "accessToken": "signed-access-token",
  "expiresIn": 3600,
  "email": "jordan.lee@healthsystem.org",
  "fullName": "Jordan Lee",
  "organization": "Enterprise Health System",
  "role": "facility-admin",
  "facility": "general-acute-care"
}
```

The refresh token is never returned in the body. The browser sends the cookie to `/api/auth/refresh` and `/api/auth/logout` automatically, and page scripts can't read it.

## How identity and role are decided

1. The server exchanges the code at the provider's token endpoint and verifies the `id_token` signature (RS256 against the provider JWKS), issuer, audience, and expiry.
2. The user's email comes from the `email`, `preferred_username`, or `upn` claim.
3. Role and facility come **only** from the user's NyxHICSlab account (created on the Admin page or with `npm run create-user`), or from `BOOTSTRAP_ADMIN_EMAILS` before any accounts exist. The email address format is never used to infer a role.
4. Users without an active account get `403`.

## Error Responses

- `400 Bad Request`: Missing fields or invalid redirect URI
- `401 Unauthorized`: Code exchange or id_token verification failed
- `403 Forbidden`: Verified user has no active NyxHICSlab account
- `429 Too Many Requests`: Rate limited
- `503 Service Unavailable`: Provider not configured on the server (fails closed; no session is issued)
- `500 Internal Server Error`: Unexpected token service error

Error bodies carry a user-safe `error` message; provider details are logged server-side only.

## Session refresh

`POST /api/auth/refresh` (no body) rotates the refresh cookie and returns the same JSON shape as above. On every refresh the account is re-checked, so a disabled user or a role change takes effect within one access-token lifetime (1 hour). Reusing a rotated refresh token revokes that whole session family.

## Frontend Integration Notes

- Frontend route: `/auth/callback`
- On success the frontend keeps the access token in `sessionStorage` and navigates to `/dashboard`
- On reload or in a new tab, the frontend calls `/api/auth/refresh` to restore the session from the cookie
- On `401` from the API, the frontend clears the session and redirects to `/login`
